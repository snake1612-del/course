# Анализ рынка вакансий Data Analyst

> Учебный SQL-проект о высокооплачиваемых вакансиях, спросе на навыки и их связи с зарплатами в объявлениях для аналитиков данных.

**Аналитический вопрос → SQL-анализ → результаты → выводы**

**Статус проекта:** Подготовлены пять аналитических запросов. В репозитории нет исходных CSV и сохранённых результатов запросов, поэтому числовые выводы и графики ожидают проверки. При разборе SQL найдены две ошибки, блокирующие корректный анализ; ниже доступны предложенные исправления и инструкции для воспроизведения.

## 📊 Обзор

Этот учебный проект использует реляционный набор данных о вакансиях, чтобы исследовать, какие позиции Data Analyst оплачиваются выше, какие навыки запрашивают работодатели и как спрос на навыки связан с указанной годовой зарплатой. Практическая цель — обоснованно выбирать навыки для дальнейшего изучения и развивать портфолио начинающего аналитика.

Анализ состоит из пяти вопросов: от отдельных вакансий до сравнения агрегированных показателей по навыкам. Первые два запроса рассматривают объявления с локацией `Anywhere` или содержащей `Moscow`; остальные три охватывают все локации в предоставленном наборе данных. Поэтому результаты нужно интерпретировать в пределах выборки каждого запроса, а не как единый рейтинг всего рынка.

### Данные и связи

| Таблица | Единица наблюдения / ключ | Роль в анализе |
|---|---|---|
| `job_postings_fact` | Одна вакансия на `job_id` | Названия позиций, локации, даты публикации и поля зарплаты |
| `company_dim` | Одна компания на `company_id` | Названия компаний; связь с вакансиями через `company_id` |
| `skills_dim` | Один навык на `skill_id` | Названия и категории навыков |
| `skills_job_dim` | Одна пара `(job_id, skill_id)` | Связь «многие ко многим» между вакансиями и навыками |

Схема задаёт первичные и внешние ключи, включая составной первичный ключ связующей таблицы, и индексы по столбцам соединений. В одной вакансии может быть несколько навыков, поэтому их количества нельзя складывать как взаимоисключающие категории.

**Ограничения данных:** Папка `csv_files/` исключена через `.gitignore`. Источник данных, период сбора, географический охват, валюта и метод нормализации зарплат не задокументированы. `salary_year_avg` используется как предоставленное поле годовой зарплаты; для сравнения стран необходимо подтвердить сопоставимость значений. Фильтр по датам отсутствует, и проект не устанавливает текущее состояние рынка. Запросы по навыкам исключают вакансии без привязанных навыков.

## 🎯 Аналитические вопросы

1. В каких вакансиях Data Analyst с указанной годовой зарплатой и локацией `Anywhere` или содержащей `Moscow` зарплаты самые высокие?
2. Какие навыки указаны в этих десяти вакансиях?
3. Какие пять навыков встречаются в наибольшем количестве вакансий Data Analyst по всем локациям?
4. Какие пятнадцать навыков связаны с самой высокой средней годовой зарплатой при наличии более 50 вакансий с указанной зарплатой на навык?
5. Какие десять навыков наиболее востребованы среди навыков с более чем 50 вакансиями с указанной зарплатой и как соотносятся их средние зарплаты?

## 🔎 Анализ

### 1. Самые высокооплачиваемые вакансии Data Analyst

**Аналитический вопрос:** В каких подходящих объявлениях указана самая высокая годовая зарплата?

**Подход:** Соединить вакансии с названиями компаний, применить фильтры по роли, локации и наличию зарплаты, затем выбрать десять вакансий по убыванию зарплаты. `LEFT JOIN` сохраняет вакансии без соответствующей компании.

**Приёмы SQL:** `LEFT JOIN`, логические фильтры, `LIKE`, `IS NOT NULL`, `ROUND`, `ORDER BY`, `LIMIT`.

**Пример SQL — предлагаемое исправление исходного фильтра:**

```sql
WHERE job_title_short = 'Data Analyst'
  AND (job_location = 'Anywhere' OR job_location LIKE '%Moscow%')
  AND salary_year_avg IS NOT NULL
ORDER BY salary_year_avg DESC
LIMIT 10;
```

[Полный запрос](project_sql/1_top_paying_jobs.sql)

**Результат:** Недоступен. Приоритет `AND / OR` в исходном запросе пропускает другие роли в Москве и вакансии `Anywhere` с пустой зарплатой. При сортировке по убыванию PostgreSQL по умолчанию ставит `NULL` первыми, поэтому такие строки могут попасть в первую десятку. Перед экспортом результатов нужно исправить фильтр.

**Вывод:** Подтверждённого рейтинга зарплат пока нет. После исправления результат будет описывать отдельные объявления в определённой географической выборке; он не устанавливает типичную зарплату или зарплату начинающего аналитика.

### 2. Навыки в высокооплачиваемых вакансиях

**Аналитический вопрос:** Какие навыки связаны с десятью подходящими вакансиями с самой высокой зарплатой?

**Подход:** CTE выбирает десять вакансий с корректно сгруппированными фильтрами роли и локации. Два `INNER JOIN` добавляют связи и названия навыков, формируя одну строку на пару «вакансия — навык».

**Приёмы SQL:** CTE, `LEFT JOIN`, `INNER JOIN`, фильтрация, `ROUND`, `ORDER BY`, `LIMIT`.

**Пример SQL — предлагаемое исправление столбца зарплаты в CTE:**

```sql
-- Внутри top_paying_jobs:
ROUND(salary_year_avg) AS salary_year_avg
-- Сохранить сортировку по исходной зарплате внутри CTE:
ORDER BY job_postings_fact.salary_year_avg DESC

-- После CTE:
SELECT top_paying_jobs.*, skills
FROM top_paying_jobs
INNER JOIN skills_job_dim
  ON top_paying_jobs.job_id = skills_job_dim.job_id
INNER JOIN skills_dim
  ON skills_job_dim.skill_id = skills_dim.skill_id
ORDER BY salary_year_avg DESC;
```

[Полный запрос](project_sql/2_top_paying_job_skills.sql)

**Результат:** Недоступен. Исходный CTE возвращает выражение без псевдонима под именем `round`, поэтому внешний `ORDER BY salary_year_avg` не может найти столбец. Псевдоним позволяет выполнить запрос; указание таблицы в сортировке CTE сохраняет ранжирование по исходной, неокруглённой зарплате.

**Вывод:** После запуска запрос позволит определить перечисленные навыки в небольшой выборке дорогих вакансий. Он не считает и не ранжирует эти навыки. Вакансии без привязанных навыков исчезают после соединений, а результат может содержать больше десяти строк.

### 3. Самые востребованные навыки

**Аналитический вопрос:** Какие навыки чаще всего встречаются в вакансиях Data Analyst?

**Подход:** Соединить вакансии с навыками, сгруппировать по названию навыка и посчитать строки связующей таблицы. Выбрать пять наибольших значений, учитывая вакансии как с зарплатой, так и без неё.

**Приёмы SQL:** `INNER JOIN`, `COUNT`, `GROUP BY`, фильтрация, `ORDER BY`, `LIMIT`.

**Пример SQL:**

```sql
SELECT skills, COUNT(skills_job_dim.job_id) AS demand_count
-- Полный запрос соединяет вакансии со связующей таблицей и справочником.
WHERE job_title_short = 'Data Analyst'
GROUP BY skills
ORDER BY demand_count DESC
LIMIT 5;
```

*В этом фрагменте опущены FROM/JOIN; для выполнения используйте полный запрос.*

[Полный запрос](project_sql/3_top_demanded_skills.sql)

**Результат:** В репозитории нет количеств и рейтинга навыков. При заданном составном ключе каждая вакансия учитывается не более одного раза на идентификатор навыка. Группировка по названиям предполагает, что название однозначно определяет навык; схема этого не гарантирует.

**Вывод:** Это наиболее широкий показатель спроса в проекте. Его значения нельзя приравнивать к спросу среди вакансий с указанной зарплатой из анализа 5.

### 4. Навыки с самой высокой средней зарплатой

**Аналитический вопрос:** Какие достаточно представленные навыки связаны с самой высокой средней годовой зарплатой?

**Подход:** Оставить вакансии Data Analyst с `salary_year_avg > 0`, рассчитать среднюю зарплату по навыкам и сохранить группы с более чем 50 различными вакансиями. Вернуть пятнадцать навыков, отсортированных по округлённой средней зарплате.

**Приёмы SQL:** `INNER JOIN`, `AVG`, `ROUND`, `COUNT(DISTINCT ...)`, `GROUP BY`, `HAVING`, `ORDER BY`, `LIMIT`.

**Пример SQL:**

```sql
WHERE job_title_short = 'Data Analyst'
  AND salary_year_avg > 0
GROUP BY skills
HAVING COUNT(DISTINCT job_postings_fact.job_id) > 50
ORDER BY avg_salary DESC
LIMIT 15;
```

[Полный запрос](project_sql/4_top_paying_skills.sql)

**Результат:** Проверенных средних зарплат нет. Порог строго больше 50, поэтому группе нужна как минимум 51 различная вакансия. Нулевые, отрицательные и пустые зарплаты исключаются.

**Вывод:** Порог уменьшает зависимость от очень малых групп, но не устраняет влияние уровня позиции, географии, состава компаний и раскрытия зарплаты. Связь навыка с зарплатой не доказывает, что этот навык сам по себе повышает оплату.

### 5. Совместное рассмотрение спроса и зарплаты

**Аналитический вопрос:** Какие часто запрашиваемые навыки также стоит исследовать с точки зрения связанных с ними зарплат?

**Подход:** Два CTE рассчитывают количество различных вакансий и округлённую среднюю зарплату для одной и той же выборки Data Analyst с положительной зарплатой. Результаты соединяются по идентификатору навыка; остаются группы с количеством выше 50 и десять навыков, отсортированных сначала по спросу, затем по зарплате.

**Приёмы SQL:** Несколько CTE, `INNER JOIN`, `COUNT(DISTINCT ...)`, `AVG`, `ROUND`, `GROUP BY`, `DISTINCT`, фильтрация, `ORDER BY` по нескольким столбцам, `LIMIT`.

**Пример SQL:**

```sql
FROM skills_demand
INNER JOIN average_salary
  ON skills_demand.skill_id = average_salary.skill_id
WHERE demand_count > 50
ORDER BY demand_count DESC, avg_salary DESC
LIMIT 10;
```

[Полный запрос](project_sql/5_optimal_skills.sql)

**Результат:** Значений спроса и зарплаты нет. В реализованном рейтинге приоритет имеет спрос; средняя зарплата используется при одинаковом спросе. Общий балл или математический критерий оптимизации отсутствует.

**Вывод:** После проверки результат может помочь обсудить приоритеты обучения, но слово «optimal» в имени файла не означает доказанного лучшего баланса зарплаты и спроса.

## 📈 Ключевые выводы

**Статус доказательств:** Без данных нельзя установить числовые закономерности рынка. Ниже приведены проверенные наблюдения о методике и интерпретации анализа, а не эмпирические рыночные выводы:

- В проекте две географические выборки: `Anywhere`/`Moscow` для анализов 1–2 и все локации для анализов 3–5. Их рейтинги отвечают на разные вопросы.
- Анализ 3 включает вакансии без раскрытой зарплаты; анализы 4–5 требуют положительную годовую зарплату. Показатель спроса в этих результатах рассчитывается на разных совокупностях вакансий.
- Для сравнения навыков по зарплате требуется как минимум 51 различная вакансия на группу. Это правило охвата, а не гарантия репрезентативности.
- Анализ 5 ставит спрос выше зарплаты. Одна только высокая зарплата не поднимает менее востребованный навык выше более востребованного.

После выполнения проверенных запросов замените эти наблюдения подтверждёнными названиями навыков, количествами и сравнениями зарплат и одновременно обновите оба README.
